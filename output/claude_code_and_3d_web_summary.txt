제1장. 클라우드 클로드 코드(Cloud Sessions / Web)의 정체와 구동 메커니즘
====================================================================================================

1. 클라우드 클로드 코드란 무엇인가?
   - 정의: 기존 로컬 터미널에서 실행되던 Anthropic의 자율 에이전틱 코딩 도구인 'Claude Code'를 사용자 로컬 PC가 아닌,
     Anthropic이 클라우드 인프라에서 관리하는 격리된 리눅스 가상머신(VM / 샌드박스 컨테이너) 환경에서 구동하는 방식입니다.
   - 접근 채널:
     1) 웹 브라우저 인터페이스: claude.ai/code 에 접속하여 직접 지시 및 세션 관리
     2) 터미널 CLI 확장: 터미널에서 `claude --cloud` 명령어를 주어 장시간 작업을 클라우드로 오프로딩
     3) 모바일/데스크톱 앱: Claude 공식 앱 내 'Code' 탭을 통해 스마트폰, 태블릿에서도 작업 지휘 가능

2. 구동 메커니즘의 차이
   - 로컬 구동 방식:
     사용자 컴퓨터의 로컬 터미널에서 실행되며, 로컬 파일시스템에 직접 접근하여 파일을 읽고 쓰고, 로컬 쉘 명령어를 실행합니다.
   - 클라우드 구동 방식:
     Anthropic 클라우드 VM이 사용자의 GitHub/GitLab 원격 저장소를 클론(Clone)받은 뒤, 그 격리된 샌드박스 컨테이너 내부에서
     코드 편집, 빌드, 의존성 설치, 테스트 실행을 자율적으로 수행하고, 완료된 결과를 Git 브랜치 및 PR(Pull Request)로 반환합니다.

3. 혼동하기 쉬운 'Remote Control'과의 명확한 구분
   - Cloud Sessions (`claude --cloud` / claude.ai/code):
     * 실행 위치: Anthropic 클라우드 VM
     * 특징: 내 컴퓨터를 꺼도 작업이 멈추지 않음. 로컬 컴퓨터의 리소스를 전혀 쓰지 않는 완전한 클라우드 작업.
   - Remote Control (`claude remote-control`):
     * 실행 위치: 사용자 본인의 로컬 PC
     * 특징: 실제 코딩과 파일 변경은 내 컴퓨터 터미널에서 돌고 있으며, 스마트폰이나 웹 브라우저는 그 로컬 세션을
       화면 밖에서 원격 조종하는 '무선 리모컨(Sync Layer)' 역할만 수행함. PC를 끄면 세션도 즉시 종료됨.

제2장. 일반 로컬 클로드 코드 vs 클라우드 클로드 코드 상세 비교 분석
====================================================================================================

1. 8대 핵심 항목 상세 비교표
┌───────────────────┬───────────────────────────────────┬───────────────────────────────────┐
│ 비교 항목         │ 일반 로컬 Claude Code (CLI)       │ 클라우드 Claude Code (Web/Cloud)  │
├───────────────────┼───────────────────────────────────┼───────────────────────────────────┤
│ 1. 실행 주체      │ 사용자 로컬 PC / 터미널           │ Anthropic 관리 클라우드 VM        │
│ 2. PC 전원 및 자원│ PC 켜둬야 함, CPU/RAM/배터리 소모 │ PC/노트북 완전 종료 가능 (자원 0) │
│ 3. 디바이스 접근성│ 개발 머신 앞에서만 조작 가능      │ 스마트폰, 태블릿, 외부 브라우저   │
│ 4. 작업 상호작용  │ 실시간 페어 프로그래밍 (빠른 핑퐁)│ 비동기 자율 작업 (지시 후 배치)   │
│ 5. 로컬 환경 접근 │ 로컬 DB, Docker, 로컬 MCP 직결 가능│ 외부 접근 불가 사내망/로컬 제한   │
│ 6. 코드 반영 방식 │ 로컬 파일시스템에 즉각 수정 반영  │ Git 원격 브랜치 생성 및 PR 제출   │
│ 7. 병렬 작업성    │ 로컬 PC 사양/터미널 창 개수 제약  │ 독립된 VM에서 여러 세션 동시 실행 │
│ 8. 보안 및 규정   │ 코드가 로컬 바깥으로 복제 안 됨   │ 코드가 클라우드 VM에 클론되어 실행│
└───────────────────┴───────────────────────────────────┴───────────────────────────────────┘

2. 클라우드 클로드 코드의 4대 핵심 장점
   ① 완전한 비동기 자율 작업 ("지시해 두고 퇴근하기"):
      수십 개 파일의 아키텍처 리팩토링, 전체 단위 테스트 커버리지 작성, 대규모 패키지 메이저 버전 업그레이드 등
      수십 분에서 수 시간 걸리는 무거운 작업을 던져두고 노트북을 덮거나 외출할 수 있습니다.
   ② 기기 독립성 (모바일/태블릿 바이브 코딩):
      무거운 Node.js, Python, 빌드 툴체인이 전혀 설치되어 있지 않은 아이패드나 스마트폰에서도
      이슈를 확인하고 기능 추가나 버그 수정을 즉시 지시할 수 있습니다.
   ③ 대규모 병렬 에이전트 구동:
      로컬에서 3~4개의 에이전트를 동시에 돌리면 CPU 100%와 팬 소음, 메모리 부족이 발생하지만,
      클라우드에서는 기능 A 개발, 기능 B 개발, 버그 수정을 각각 독립된 VM에서 병렬로 구동할 수 있습니다.
   ④ 호스트 PC 오염 방지:
      에이전트가 패키지를 잘못 설치하거나 환경 설정을 꼬이게 만들어도 작업이 끝나면 VM이 소멸하므로 내 PC가 안전합니다.

3. 클라우드 클로드 코드의 4대 한계점
   ① 시각적 피드백 루프의 지연:
      UI 디자인의 1px 패딩 수정, 색상 변경, 문구 수정 등 즉각적인 눈대중 피드백이 필요한 작업은
      터미널과 브라우저 핫 리로딩이 연결된 로컬 CLI가 훨씬 빠르고 쾌적합니다.
   ② 폐쇄망 및 사내망 로컬 리소스 접근 불가:
      내 로컬 호스트(`localhost:5432`)에 띄워둔 테스트 DB, 사내 VPN 내부에 있는 프라이빗 API 서버,
      로컬 전용 하드웨어 장치 등은 클라우드 VM에서 접근하기 어렵습니다.
   ③ Git 연동 강제:
      아직 Git에 올리지 않은 임시 스크래치 코드나 아이디어 단계의 로컬 파일은 클라우드로 바로 보낼 수 없으며,
      반드시 원격 Git 리포지토리가 연결되어 있어야 합니다.
   ④ 기업 코드 반출 보안 정책:
      소스코드의 외부 클라우드 업로드가 엄격히 통제되는 금융/보안 중심 엔터프라이즈 환경에서는 도입 제약이 있습니다.

4. 상황별 실무 선택 가이드
   - 로컬 Claude Code 추천:
     * 화면을 직접 보면서 UI/UX 디자인을 실시간으로 다듬을 때
     * 로컬 Docker, 로컬 SQLite/PostgreSQL 데이터베이스와 직접 붙여서 디버깅할 때
     * 오타 수정, 단일 함수 수정 등 1~2분 안에 끝나는 초단기 피드백 작업
   - 클라우드 Claude Code 추천:
     * 퇴근 전/취침 전 장시간 걸리는 대규모 리팩토링이나 테스트 통과 작업
     * 이동 중이거나 외출 시 스마트폰/태블릿으로 긴급 버그 수정이나 새 기능 추가 지시
     * 프로젝트 3~4개 브랜치를 동시에 파서 각각 다른 기능을 병렬로 구현시킬 때

제3장. PRD(제품요구명세서)를 활용한 MVP 및 프로토타입 웹앱/앱 제작 전략
====================================================================================================

1. 0에서 1을 만드는 최적의 하이브리드 워크플로우 (클라우드 + 로컬 시너지)
   - [1단계: 클라우드] 초기 뼈대(Scaffolding) 및 보일러플레이트 일괄 구축
     * 작업: 빈 GitHub 저장소에 PRD 문서를 첨부하고 클라우드 세션에 지시.
     * 프롬프트 예시: "첨부된 PRD를 기반으로 Next.js + Tailwind CSS + SQLite 기반 프로젝트를 초기화하고,
       회원가입/로그인 흐름, 핵심 데이터 모델 및 CRUD API 라우트, 페이지 기본 레이아웃을 모두 구현해서 브랜치로 PR 올려줘."
     * 효과: 패키지 설치 대기, 폴더 구조 잡기, 설정 파일 구성 등 수작업으로 지루한 초기 세팅을 기다림 없이 완료.
   - [2단계: 로컬] 실시간 눈(Eye) 코딩 및 인터랙션 디테일 튜닝
     * 작업: 클라우드가 생성한 PR 브랜치를 로컬로 `git pull` 받고 `npm run dev` 실행.
     * 작업 내용: 버튼 위치, 애니메이션 속도, 폼 유효성 검사 문구, 반응형 모바일 레이아웃 조정.
     * 효과: 실시간 핫 리로딩(Fast Refresh)을 통해 화면을 보며 빠른 핑퐁으로 완성도 극대화.
   - [3단계: 클라우드] 안정화 및 테스트 자동화 위임
     * 작업: 핵심 화면과 플로우가 갖춰진 코드를 커밋하고 다시 클라우드에 전달.
     * 프롬프트 예시: "핵심 기능 구현이 완료되었으니, 전체 페이지에 에러 바운더리를 적용하고
       주요 비즈니스 로직에 대한 Jest 단위 테스트 코드를 작성해서 빌드 오류를 검증해줘."

2. 플랫폼별 제작 환경의 결정적 차이
   - 웹 애플리케이션 (Web App):
     * 초기 뼈대(클라우드) ➔ UI 디테일(로컬)의 하이브리드 전략이 완벽하게 들어맞음.
   - 모바일 애플리케이션 (React Native / Flutter):
     * **로컬 Claude Code가 압도적으로 유리.**
     * 이유: 모바일 앱은 iOS 시뮬레이터(Xcode), 안드로이드 에뮬레이터(Android Studio), 또는 실물 스마트폰에
       직접 앱을 띄워 터치 제스처, 카메라/센서 권한, 네이티브 빌드를 실시간으로 확인해야 하기 때문.
       클라우드 리눅스 VM에서는 모바일 GUI 시뮬레이터를 띄워 보기가 매우 어렵습니다.

제4장. 타 계정 작업물을 내 로컬 클로드 코드로 완벽하게 인수인계하는 방법
====================================================================================================

1. 계정 독립성의 원리
   - 클라우드 클로드 코드는 결과물을 앤트로픽 내부 DB에 가두지 않고 표준 Git 커밋/PR 형태로 저장합니다.
   - 따라서 작업한 Anthropic 계정과 가져와서 개발할 Anthropic 계정이 완전히 달라도,
     **Git 원격 저장소(GitHub/GitLab)**를 매개로 100% 매끄럽게 인수인계할 수 있습니다.

2. 단계별 실행 절차
   - 1단계 (A 계정/클라우드):
     * 클라우드 세션에서 작업한 브랜치를 원격 GitHub 저장소에 푸시(또는 PR 생성)합니다.
     * 해당 저장소에 내 GitHub 계정(B)을 협업자(Collaborator)로 초대하거나 저장소를 Fork합니다.
   - 2단계 (B 계정/로컬 PC):
     * 내 로컬 PC 터미널을 열고 코드를 클론합니다:
       `git clone <저장소-URL>`
       `cd <프로젝트-폴더>`
   - 3단계 (로컬 클로드 코드 기동):
     * 해당 프로젝트 폴더 안에서 내 계정으로 로그인된 클로드 코드를 실행합니다:
       `claude`
     * 로컬 클로드 코드는 현재 폴더의 파일 트리와 Git 변경 로그를 즉시 스캔하여 작업 상태를 파악합니다.

3. 컨텍스트 완벽 인수인계 팁
   - `CLAUDE.md` 파일 활용:
     프로젝트 루트에 기술 스택, 아키텍처 규칙, 빌드/테스트 명령어가 적힌 `CLAUDE.md`가 포함되어 있으면,
     로컬 클로드 코드가 첫 실행 시 이를 읽고 이전 계정이 작업하던 규칙과 스타일을 그대로 유지합니다.
   - 인수인계 첫 프롬프트 추천:
     "이 프로젝트는 다른 환경에서 클라우드 클로드 코드로 제작된 웹앱이야.
      현재 전체 아키텍처, 구현된 핵심 기능, 그리고 아직 구현되지 않은 TODO 항목을 먼저 분석해서 브리핑해줘."

제5장. 패키지 설치 및 외부 생성형 AI(Meshy.ai, Higgsfield) MCP 심층 연동
====================================================================================================

1. 클라우드 세션에서의 패키지/라이브러리 설치
   - 동작 여부: **100% 완전 지원**
   - 세부 사항:
     * 앤트로픽 클라우드 VM 내에서 `npm install`, `pip install`, `cargo`, `apt` 등의 명령어가 정상 실행됩니다.
     * 설치된 라이브러리는 `package.json`이나 `requirements.txt`에 기록되어 최종 Git 커밋에 함께 포함됩니다.
     * 패키지 설치 후 빌드(`npm run build`), 테스트 실행까지 클라우드 안에서 완결됩니다.

2. 클라우드 환경에서의 MCP (Model Context Protocol) 지원 현황
   - MCP 전송 프로토콜의 차이:
     * `stdio` 방식: 로컬 PC 내부 프로세스를 직접 띄워 표준 입출력으로 통신하는 방식.
     * `HTTP/SSE` 방식: 웹/클라우드 서버에 배포된 MCP 엔드포인트와 인터넷을 통해 통신하는 방식.
   - 클라우드 클로드 코드에서는 인터넷 통신이 가능한 **원격(Remote) HTTP/SSE 기반 MCP** 및
     컨테이너 내에서 자율 실행 가능한 표준 패키지(`npx -y @...`) 기반 MCP가 완벽하게 작동합니다.
     (단, 내 로컬 PC에만 떠 있는 `localhost` 서버는 클라우드에서 직접 접근 불가)

3. Meshy.ai (3D 모델 생성) 및 Higgsfield (비디오/모션 생성) 연동 원리
   - 서비스 성격:
     두 서비스 모두 사용자의 로컬 하드웨어가 아닌 자체 클라우드 GPU 인프라에서 AI 모델을 추론하는 웹 SaaS입니다.
   - 동작 메커니즘:
     ① 클라우드 클로드 코드가 프롬프트를 인식하고 Meshy/Higgsfield MCP Tool을 호출.
     ② API Key를 통해 외부 Meshy/Higgsfield 서버로 3D 모델(텍스트 to 3D) 또는 비디오 생성 요청 전송.
     ③ 생성 완료 시 반환되는 결과물(.glb 3D 파일, .mp4 비디오 파일)을 다운로드하여 프로젝트의 `public/assets/` 폴더에 자동 저장.
     ④ 클라우드 클로드 코드가 해당 3D 파일이나 비디오를 Three.js 뷰어 또는 HTML5 비디오 컴포넌트에 연결하는 코드까지 작성.
   - 비동기 생성의 극대화된 장점:
     고품질 3D 모델이나 4K 비디오 생성은 통상 1분~3분 이상의 대기 시간이 발생합니다.
     로컬에서는 터미널을 켜두고 기다려야 하지만, 클라우드 클로드 코드에서는 "캐릭터 3종을 3D로 생성해서 갤러리에 넣어둬"라고
     던져두고 창을 닫아도 백그라운드에서 생성이 끝날 때까지 대기했다가 파일을 받아 코드를 완성합니다.

4. 프로젝트 단위 `.mcp.json` 설정 파일 작성법
   프로젝트 루트에 `.mcp.json`을 작성하면 클라우드 및 로컬 세션 모두에서 공통으로 도구가 로드됩니다.
   ```json
   {
     "mcpServers": {
       "meshy": {
         "command": "npx",
         "args": ["-y", "@meshy/mcp-server"],
         "env": {
           "MESHY_API_KEY": "${MESHY_API_KEY}"
         }
       }
     }
   }
   ```
   *보안 주의사항: API Key가 GitHub 공개 저장소에 그대로 노출(Push)되지 않도록, 반드시 환경변수나 Secret 저장소를 통해 주입해야 합니다.*

제6장. 현대 웹 개발의 양대 축: Next.js와 Three.js의 본질과 시너지
====================================================================================================

1. 직관적인 비유
   - **Next.js**: 건물의 기초 토대, 기둥, 배관, 출입문, 전기 배선 (웹사이트의 전체 뼈대와 인프라)
   - **Three.js**: 그 건물 거실 한가운데에 설치된 초고화질 3D 입체 홀로그램 전시관 (3D 그래픽 엔진)

2. Next.js 심층 분석
   - 정의: Vercel에서 개발한 전 세계 표준 React 기반 풀스택 웹 애플리케이션 프레임워크.
   - 해결한 문제:
     * 순수 React(CSR)의 치명적 단점인 검색엔진 최적화(SEO) 미흡 및 초기 느린 흰 화면 로딩 문제를 해결.
   - 핵심 기능:
     * SSR (서버 사이드 렌더링) & SSG (정적 생성): 사용자가 페이지를 열기 전에 서버에서 HTML을 미리 렌더링하여 초고속 전달.
     * App Router: 폴더 구조 기반 직관적인 자동 페이지 라우팅 (`app/dashboard/page.tsx`).
     * 풀스택 API 라우트: 별도 백엔드(Express 등) 없이도 데이터베이스 조회, 결제 연동, 인증 로직을 한 프로젝트 안에서 처리.

3. Three.js 심층 분석
   - 정의: 웹 브라우저에서 그래픽카드(GPU)를 활용해 3D 그래픽을 렌더링하는 WebGL을 사람이 다루기 쉽게 추상화한 자바스크립트 3D 라이브러리.
   - 해결한 문제:
     * 저수준 WebGL은 점 하나를 찍는 데도 복잡한 수학 공식과 수백 줄의 셰이더 코드가 필요했음.
     * Three.js는 이를 무대 연출 방식의 4대 개념으로 단순화:
       1) Scene (장면/무대): 3D 오브젝트들이 배치되는 3차원 가상 공간
       2) Camera (카메라): 사용자가 그 공간을 바라보는 시점 (원근 카메라, 직교 카메라)
       3) Light (조명): 그림자와 입체감을 만드는 빛 (자연광, 점광원, 스포트라이트)
       4) Mesh (물체): 뼈대(Geometry) + 표면 질감/색상(Material)
   - 장점: 별도 플러그인 설치 없이 모바일/데스크톱 브라우저에서 3D 모델(.glb, .gltf)을 부드럽게 렌더링.

4. 두 기술의 결합 시너지 (Next.js + Three.js)
   - 실제 React 생태계에서는 Three.js를 직접 쓰기보다 **`React Three Fiber (R3F)`**라는 리액트 선언형 래퍼를 사용합니다.
   - 대표적 활용 사례:
     * 애플(Apple) 스타일 제품 소개 페이지: 스크롤에 따라 3D 기기가 회전, 분해, 조립되는 시각 효과.
     * 인터랙티브 3D 쇼핑몰: 가구, 의류, 자동차를 360도 회전하며 재질과 색상을 실시간으로 변경해보고 장바구니에 담는 기능.

제7장. 캔버스 라이브러리(Canvas Library)의 원리와 대표 도구 비교
====================================================================================================

1. HTML5 `<canvas>`의 태생적 한계
   - 웹 브라우저에 투명한 '빈 도화지'를 깔아두고 픽셀 단위로 그림을 그리는 태그.
   - 순수 캔버스 API는 '지우개로 싹 지우고 다시 그리기(Clear and Redraw)' 방식:
     * 사각형을 하나 그리고 마우스로 드래그하려면, 마우스 좌표 계산, 이전 프레임 지우기, 새 위치에 그리기를
       초당 60회씩 개발자가 수학적으로 직접 구현해야 함.
     * 도형을 클릭했는지(이벤트 리스너) 감지하는 기능조차 기본으로 제공되지 않음.

2. 캔버스 라이브러리의 역할
   - 번거롭고 복잡한 도화지 코딩을 **피그마(Figma)나 파워포인트(PPT)**처럼 '객체(Object)' 단위로 조작할 수 있게 감싸준 도구.
   - 단 몇 줄로 드래그 앤 드롭, 모서리 잡고 크기 조절, 회전, 레이어 순서 변경, 그룹화가 가능해짐.

3. 대표 5대 캔버스 라이브러리 비교
┌──────────────┬──────────────────────────────────┬────────────────────────────────────────────────────────┐
│ 라이브러리   │ 주요 특화 분야                   │ 실제 활용 사례                                         │
├──────────────┼──────────────────────────────────┼────────────────────────────────────────────────────────┤
│ Fabric.js    │ 2D 그래픽 편집 / 객체 조작       │ 포토샵 웹 버전, 스티커 사진 꾸미기, 굿즈 커스텀 툴     │
│ Konva.js     │ 다이어그램 / 평면도 / 화이트보드 │ 미로(Miro) 스타일 화이트보드, 좌석 배치도, 평면도 도면 │
│ Pixi.js      │ 초고속 2D GPU 렌더링             │ 대규모 웹 2D 인터랙션, 수만 개 파티클(먼지/불꽃) 효과  │
│ Phaser       │ 종합 2D 웹 게임 엔진             │ 2D 플랫폼 게임, 쿠키런 류 러닝 게임 (물리/사운드 내장) │

└──────────────┴──────────────────────────────────┴────────────────────────────────────────────────────────┘

4. 일반 HTML/CSS vs 캔버스 라이브러리 사용 기준
   - 일반 HTML/CSS: 로그인 폼, 게시판, 쇼핑몰 리스트 등 정형화된 네모 형태의 UI
   - 캔버스 라이브러리: 자유로운 마우스 드로잉, 스티커 조작, 캔버스 이미지 저장(PNG 내보내기), 2D 게임

제8장. 3D 모델 텍스처/텍스트/데칼(Decal) 올인원 구현 및 패키지 통합 스택
====================================================================================================

1. 사용자의 핵심 우려 및 오해 해소
   - 질문: "3D 모델에 글자도 치고, 이미지도 올리고, 3D 표면에 스티커도 착 붙이고 싶은데,
           패키지를 다 따로 깔아서 충돌하는 건 아닌가? 내가 직접 .js 라이브러리를 만들 수는 없는데?"
   - 명쾌한 해답:
     직접 라이브러리를 만들 필요가 전혀 없습니다!
     현대 웹 개발에서는 **React Three Fiber (R3F)**를 중심 축으로 삼으면,
     2D 편집(Fabric.js)과 3D 데칼 스티커(Drei Decal)가 **하나의 유기적인 파이프라인으로 통합**됩니다.

2. 통합 아키텍처 구조도
   ┌───────────────────────────────────────────────────────────────────────────────────────────────┐
   │                                  Next.js 풀스택 웹 애플리케이션                               │
   │                                                                                               │
   │   [왼쪽 영역: 2D 커스텀 에디터]                      [오른쪽 영역: 3D 뷰어 & 데칼]            │
   │   ┌───────────────────────────┐                      ┌─────────────────────────────┐          │
   │   │        Fabric.js          │                      │    React Three Fiber (R3F)  │          │
   │   │  - 텍스트 입력 및 폰트 변경│                      │    - 3D 모델(.glb) 렌더링   │          │
   │   │  - 이미지 업로드/회전/크기│                      │    - 마우스 360도 회전/줌   │          │
   │   └─────────────┬─────────────┘                      └──────────────┬──────────────┘          │
   │                 │ (실시간 동기화)                                   │                         │
   │                 ▼                                                   ▼                         │
   │   THREE.CanvasTexture (2D 캔버스를 텍스처로 투영)    @react-three/drei <Decal />              │
   │   ➔ 3D 티셔츠/머그컵 전체 피부에 실시간 인쇄 반영     ➔ 3D 곡면을 클릭한 위치에 스티커 직접 부착│
   └───────────────────────────────────────────────────────────────────────────────────────────────┘

3. 설치해야 할 표준 패키지 (단 한 줄)
   터미널에서 아래 명령어만 실행하면 모든 핵심 기능이 준비됩니다:
   ```bash
   npm install three @react-three/fiber @react-three/drei fabric
   ```
   - `three`: 3D 그래픽 코어 엔진
   - `@react-three/fiber`: Three.js를 React 컴포넌트 형태로 선언할 수 있게 해주는 프레임워크
   - `@react-three/drei`: 3D 표면에 스티커를 바로 쏘아붙이는 **`<Decal />`** 컴포넌트 기본 내장
   - `fabric`: 텍스트 타이핑, 이미지 크기/회전 조절을 담당하는 2D 캔버스 엔진

   *(참고: Spline 3D의 경우 패키지를 무겁게 깔 필요 없이, spline.design 웹 툴에서 예쁘게 씬을 구성한 뒤
    '.glb' 파일로 내보내기(Export)하여 위 Three.js 뷰어에 그대로 로드하면 됩니다.)*

4. 세 가지 핵심 기능의 작동 원리
   ① 2D 텍스트/이미지 편집 ➔ 3D 모델 전체 표면에 입히기:
      - Fabric.js 인스턴스에서 사용자가 글자를 쓰거나 사진을 올리면,
      - Three.js의 `THREE.CanvasTexture(fabricCanvas.getElement())`가 해당 도화지를 텍스처로 변환하여
      - 3D 모델 재질의 `map` 속성에 꽂아줍니다. `texture.needsUpdate = true` 처리만 해주면 실시간 연동 완료.
   ② 3D 표면에 직접 클릭해서 스티커 붙이기 (Decal 기법):
      - 3D 모델의 특정 곡면(신발, 티셔츠 가슴 부위 등)을 마우스로 클릭하면,
      - 클릭된 3차원 교차점 좌표(Raycasting Point)와 법선 벡터(Normal)를 감지하여
      - `@react-three/drei`의 `<Decal position={point} rotation={rotation} map={stickerTexture} />`를 마운트합니다.
   ③ 3D 모델 생성 자동화 (Meshy.ai 연계):
      - 클로드 코드에게 "Meshy MCP로 모자 3D 모델을 생성해줘"라고 지시하면 `.glb` 파일이 생성되고,
      - 이를 R3F의 `useGLTF('/assets/hat.glb')`로 화면에 즉시 띄웁니다.

5. AI(클로드 코드) 바이브 코딩 실전 프롬프트 템플릿
   사용자가 직접 복잡한 자바스크립트 연결 코드를 짤 필요 없이, 아래와 같이 클로드 코드에게 지시하면 완벽하게 구현됩니다:

   [프롬프트 예시]
   "Next.js 프로젝트에서 `three`, `@react-three/fiber`, `@react-three/drei`, `fabric`을 사용해서
    3D 제품 커스터마이저 컴포넌트를 만들어줘.
    
    요구사항:
    1. 화면 좌측에는 Fabric.js 기반 2D 캔버스를 배치해서 사용자가 텍스트를 입력하고 폰트를 바꾸며,
       이미지를 업로드하고 회전/스케일할 수 있게 해줘.
    2. 화면 우측에는 Three.js Canvas를 띄우고 기본 3D 티셔츠(또는 큐브/실린더) 모델을 렌더링해줘.
    3. 좌측 Fabric.js의 2D 디자인 내용이 `CanvasTexture`를 통해 실시간으로 3D 모델 표면에 반영되어야 해.
    4. 추가 모드로 '스티커 붙이기(Decal)' 버튼을 만들어, 3D 모델 표면을 직접 클릭했을 때
       `@react-three/drei`의 `<Decal />` 컴포넌트를 사용해 해당 위치에 스티커가 착 달라붙게 구현해줘."
