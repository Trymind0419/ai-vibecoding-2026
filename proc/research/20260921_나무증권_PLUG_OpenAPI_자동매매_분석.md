# 나무증권(NH투자증권) PLUG Open API 종합 분석 및 주식 자동매매 프로그램 구현 리서치

> **도메인**: ORD/MKT (주식 주문 및 시세/자동매매)  
> **작성일**: 2026-09-21  
> **상태**: 조사 완료 / 구현 제안  
> **참조**: [PLUG-OpenAPI GitHub](https://github.com/PLUG-OpenAPI), [나무 PLUG 공식 포털](https://www.nhplug.com), [llms.txt](https://www.nhplug.com/llms.txt)

---

## 1. 개요 및 배경

사용자는 나무증권(NH투자증권) OpenAPI를 활용하여 주식 자동매매 프로그램을 구축하고자 함.  
NH투자증권은 차세대 오픈 API 플랫폼인 **'NHPLUG (나무 플러그 · N2 플러그)'**와 공식 GitHub 조직 **`PLUG-OpenAPI`**를 통해 개발자 및 AI 에이전트 전용 개발 환경을 제공하고 있음.

본 문서는 `PLUG-OpenAPI` 생태계(저장소, SDK, MCP, 공식 명세)를 전수 분석하고, 이를 기반으로 안정적인 주식 자동매매 시스템을 설계·구현하기 위한 기술적 요구사항 및 아키텍처를 제시함.

## 2. PLUG-OpenAPI 생태계 및 리소스 종합 분석

### 2.1 주요 저장소 구성 (`github.com/PLUG-OpenAPI`)
1. **`nhplug-sdk` (공식 Python SDK)**
   - PyPI 패키지명: `nhplug` (`pip install nhplug`)
   - 주요 기능: 인증 및 24시간 토큰 파일 캐시, REST 호출 자동 스로틀(초당 4회), `Input_0` 봉투 래핑, 응답 연속조회(`paginate`/`cts`), WebSocket 실시간 멀티세션 자동 관리(10개 제한 분할), 종목 마스터(.mst) 바이너리 파서(28종), OS 신뢰 인증서 연동(`truststore`).
   - 자동매매 개발의 핵심 기반 라이브러리.
2. **`nhplug-mcp` (Model Context Protocol 로컬 서버)**
   - Claude Desktop 또는 에이전트형 AI와 대화형으로 연동하여 시세 및 계좌를 조회하는 도구.
   - 주문 기능은 안전을 위해 기본 비활성화(`NHPLUG_ENABLE_TRADING=false`).
3. **`.github` (프로필 및 공통 설정)**
   - PLUG OpenAPI 전체 아키텍처 안내 및 빠른 시작 가이드 제공.

### 2.2 공식 포털 및 명세 정본 (Single Source of Truth, SSOT)
- **공식 포털**: 나무 [www.nhplug.com](https://www.nhplug.com) (앱키/시크릿 발급)
- **AI/LLM 명세 요약**: `https://www.nhplug.com/llms.txt` (전체 문맥: `llms-full.txt`)
- **자산군별 OpenAPI 명세**: `https://www.nhplug.com/openapi-docs/<자산군>/openapi.json`
  - `common`: 토큰 발급 및 계좌 목록 (선행 필수)
  - `krstock`: 국내주식 시세, 잔고, 주문 (현금/신용 매수/매도, 정정/취소)
  - `gbstock`: 해외주식
  - `krfuture`, `gbfuture`, `krbond`, `krgold`: 파생상품, 채권, 금현물 등

## 3. 나무증권 Open API 핵심 기술 규약 및 주의사항

자동매매 프로그램 제작 시 반드시 준수해야 하는 치명적 규칙들:

| 구분 | 주요 규약 및 동작 메커니즘 | 주의 및 대응 방안 |
|---|---|---|
| **접근 토큰 (OAuth2)** | `POST /oauth2/token`<br>유효기간 24시간, 파일 기반 공유 캐시(`~/.nhplug/token-*.json`) 권장 | 매 호출 시 재발급 절대 금지 (재발급 1회당 사용자 보안 알림 발생). 재발급은 오직 **HTTP 401(토큰 무효)** 시에만 수행. |
| **운영 / 모의투자 분리** | 운영(Live): `api.nhplug.com:8443`<br>모의(Mock): `moapi.nhplug.com:8443` | **토큰 발급 엔드포인트는 운영 전용** (모의투자 미제공, 모의투자 호출 시에도 운영에서 받은 토큰 사용).<br>초기 자동매매 개발 및 검증은 무조건 `moapi` 환경에서 진행 필수. |
| **계좌 구분 (`acct_type`)** | `01`: 운영(일반), `02`: 운영(주문대리인), `03`: 모의투자 | `acct_type`과 접속 도메인이 불일치하면 즉시 실패. 계좌목록(`POST /n2/acctinfo`)의 첫 계좌를 맹목적으로 사용 금지. |
| **호출 유량 제한 (Throttle)** | 실측 초당 약 5회 상한 | 초과 시 `IGW42902 (429 Too Many Requests)` 반환. 재시도로 해결되지 않으므로 호출 간격(초당 4회, 250ms 슬라이딩 윈도우)을 라이브러리 차원에서 제어해야 함. |
| **KRX 시간연장 필수 파라미터** | 명세 260911 개정<br>정규장/전체장 구분 파라미터 | 시세조회(`currentDaily` 등): `view_main_yn="Y"`<br>잔고조회(`balance` 등): `aly_qut_cd="1"` (정규장) 필수 입력. 누락 시 100% 호출 실패. |
| **성공/실패 판정 원칙** | HTTP 200이 비즈니스 성공을 의미하지 않음 | `if rsp_cd == "00000"` 단일 코드 하드코딩 금지. 응답 내 기대 블록(`Output_0`) 존재 여부와 `rsp_msg` 문장을 기준으로 검증한 뒤 다음 단계(주문 등) 진행. |
| **연속조회 (`cts`)** | 대량 데이터 페이징 키 | 본문뿐 아니라 **응답 헤더(`cts`, `cts_flag`)**로 전달되는 경우가 많음. 직전 `cts`와 동일한 키가 반환되면 무한루프 방지를 위해 즉시 중단. |
| **실시간 스트리밍 (WebSocket)** | 국내 시세 및 체결통보: `7070` 포트<br>해외 시세: `7080` 포트<br>모의투자: `17070` 포트 | 주소 끝 `/websocket` 경로 필수. 앱키당 동시 세션 2개, 세션당 등록 10개 한도(초과 시 에러 메시지 없이 Close 1000 종료되므로 세션 분할 필수). |
| **수수료 경쟁력** | 국내주식 1bp (0.01%), 해외주식 9bp (0.09%) | 국내 증권사 최저가 수준으로 잦은 리밸런싱 및 알고리즘 매매에 유리함. |

## 4. 자동매매 아키텍처 방안 비교

### Option A: 공식 SDK(`nhplug`) 기반 모듈러 자동매매 파이프라인 ⭐ (권장)
- **개념**: 공식 `nhplug` SDK를 코어로 활용하고, `SPARK-IPO` 구조(전략 수립, 리스크 관리, 주문 집행, 모니터링)로 모듈화.
- **장점**:
  - 인증/토큰 캐싱, 유량 제한(4회/초), 연속조회, WebSocket 멀티세션 자동 분할, OS TLS 인증서(`truststore`) 문제 해결 완료.
  - 모의투자/운영 환경 전환이 `.env` 설정 1줄로 가능.
  - 종목 마스터(.mst) 바이너리 파서가 내장되어 있어 전 종목 티커/명칭을 손쉽게 로딩 가능.
  - 주문 전 `dry_run=True` 안전 모드 기본 제공.
- **단점**: Python 3.10+ 필요 (현재 대다수 표준 환경 충족).

### Option B: 순수 `requests` + `websockets` 원시 구현
- **개념**: 외부 SDK 없이 자체적으로 HTTP/WebSocket 통신 클래스를 작성.
- **장점**: 서드파티 의존성 제로.
- **단점**: 24시간 토큰 파일 캐싱, 401 발생 시에만 재발급하는 로직, 429 회피용 슬라이딩 윈도우 스로틀, 헤더 기반 `cts` 페이징, WebSocket 10개 종목 세션 분할 등을 모두 직접 구현해야 하므로 개발 비용이 크고 장애 위험(토큰 중복 발급으로 계정 잠김 등)이 높음.

### Option C: `nhplug-mcp`를 통한 대화형 에이전트 매매
- **개념**: Claude Desktop/에이전트가 MCP를 통해 자연어로 매매 판단 및 주문.
- **장점**: 코딩 최소화, 자연어 기반 유연한 분석.
- **단점**: 초단타나 주기적 자동 백그라운드 스케줄링 불가. 주문 실행을 AI가 직접 내리기에는 환각(Hallucination) 및 레이턴시 위험 존재.

## 5. 권장 구현 아키텍처 및 파이프라인 (SPARK + IPO 체계)

```
[IPO 데이터 흐름]
input/       -> 종목 마스터, 설정 파일 (.env, trading_config.json)
proc/        -> 프로세스 관리 (spec, plan, research)
src/         -> 자동매매 코어 엔진
  ├── config/        (환경설정 및 계좌 선택)
  ├── market/        (REST 시세 조회 및 WebSocket 실시간 체결 수집)
  ├── strategy/      (전략 시그널 생성 - 이동평균, 변동성돌파 등)
  ├── risk/          (리스크 매니저 - 손절/익절, 최대 보유비중, 예수금 체크)
  └── execution/     (주문 집행 엔진 - dry-run, moapi 검증, 실주문)
data/        -> 주문 이력 및 체결 DB (SQLite)
output/      -> 일별 매매 리포트 및 로그
```

## 6. 구현 단계 (Phase별 로드맵)

1. **Phase 1: 개발 환경 구성 및 인증 검증**
   - 가상환경(`python -m venv .venv`) 및 `nhplug[instruments,tls]` 설치
   - `.env` 설정 (모의투자 `moapi.nhplug.com:8443` 기준)
   - 토큰 자동 발급 및 계좌 번호(`acct_type="03"`) 정상 조회 검증
2. **Phase 2: 시장 데이터 및 종목 마스터 수집**
   - 국내주식 종목 마스터(`m_new_stock.mst`) 다운로드 및 KOSPI/KOSDAQ 대상 종목 유니버스 필터링
   - 현재가 및 일봉 데이터 조회 모듈 작성
3. **Phase 3: 전략 및 리스크 관리 엔진 구현**
   - 목표 전략 구현 (예: 변동성 돌파 전략 또는 단기 이평선 크로스 전략)
   - 1회 주문 한도, 일일 최대 손실 한도(-2% 강제 청산 등) 안전장치 탑재
4. **Phase 4: 모의투자 환경 기반 주문 집행 및 실시간 체결 모니터링**
   - `order_cash_buy` / `order_cash_sell` 연동 (모의계좌)
   - 실시간 체결가(`mc`) 및 체결 통보(`d2`) WebSocket 연동
5. **Phase 5: 운영(Live) 환경 전환 및 관제**
   - 충분한 모의투자 검증 후 `NHPLUG_BASE_URL`을 운영(`api.nhplug.com:8443`)으로 전환
   - 알림(텔레그램/슬랙) 연동 및 일별 매매 리포트 생성

## 7. 주요 리스크 및 안전 수칙

1. **모의투자 선검증 원칙**: 모든 전략 로직과 주문 코드는 반드시 `moapi.nhplug.com:8443` 모의투자 계좌에서 최소 수일간 검증해야 함.
2. **토큰 재발급 루프 방지**: 코드가 비정상 종료되더라도 토큰 재발급이 반복되지 않도록 파일 캐시 사용 필수 (반복 재발급 시 계정 차단 및 보안 알림 폭탄 발생).
3. **HTTP 200 오판 금지**: 주문 접수 API 호출 후 `Output_0`의 주문번호 존재 여부 및 `rsp_msg`를 확인하지 않고 성공으로 간주하면 주문 누락 발생 위험.
4. **KRX 시간연장 파라미터 누락 주의**: `aly_qut_cd="1"` 누락 시 잔고 조회가 실패하므로 예수금 체크 단계에서 주문 중단될 수 있음.
