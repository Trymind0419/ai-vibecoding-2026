# SPARK Plan: 자동매매 봇 실제 매수/매도 실행 엔진 구현

## 1. 개요
사용자가 '자동매매 시작'을 눌렀음에도 실제 주문이 나가지 않았던 원인을 해결하고, 변동성 돌파 진입 로직 및 익절/손절 청산 로직을 백그라운드 루프에 탑재하여 실시간 매매를 자동 집행하도록 구현한다.

---

## 2. 작업 단계
- [x] **1단계: 원인 분석 및 시세 데이터 규격 확인**
  - 기존 `bot.py`의 `run_loop()`가 단순 로그만 출력하는 빈 껍데기 루프였음을 식별
  - 나무증권 OpenAPI `/krstock/quote/v1/currentPrice`의 시가(`stck_oprc`), 고가(`stck_hgpr`), 저가(`stck_lwpr`), 현재가(`stck_prpr`) 필드 확인
- [x] **2단계: 변동성 돌파 전략 고도화 (`auto_trader/strategy.py`)**
  - 시가, 고가, 저가 기반 목표가 계산 수식 및 진입/청산 판별 메서드 정립
- [x] **3단계: 자동매매 봇 실행 엔진 구현 (`auto_trader/bot.py`)**
  - 감시 대상 종목(`TARGET_SYMBOLS` + 실시간 추천 종목) 자동 스캔
  - 변동성 돌파 임계값 도달 시 1회 추천 예산 범위 내 자동 매수 주문
  - 보유 종목 실시간 수익률 계산 및 익절(+3%) / 손절(-2%) 자동 매도 집행
  - 실시간 활동 로그(Activity Logs) 기록
- [x] **4단계: 백엔드 로그 API 라우트 추가 (`auto_trader/main.py`)**
  - `GET /api/v1/bot/logs` 추가
- [x] **5단계: 프론트엔드 대시보드 활동 콘솔 연동 (`index.html`, `script.js`)**
  - 트레이딩 데스크 내 실시간 봇 활동 터미널 로그 콘솔 추가
  - 봇 동작 시 2초 주기로 봇의 판단 및 매매 내역을 UI에 동적 출력
- [x] **6단계: 통합 테스트 및 검증**
  - 자동매매 시작 시 실제 주문이 체결되고 보유 종목 및 로그가 실시간 업데이트되는지 확인
